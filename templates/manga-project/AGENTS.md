# 漫画プロジェクトの作業ルール

## 複数ページの単調化を防ぐ必須ゲート

- 2ページ以上の漫画では、脚本・画風設計・画像生成・PNGレビューの各工程で `.agents/skills/manga-series-variation/SKILL.md` を必須として使う。レビュー重点の低さを理由に省略しない。
- 最初の完成画像を生成する前に、依頼範囲の全ページについて `docs/production/PAGE-VARIATION.md` へページ機能、因果、コマ設計、主ビジュアル、感情と演技、会話の働き、情報提示、前ページとの差分を記録する。未設計のまま生成せず、項目を埋めただけでPLAN GATEを合格にしない。
- 固定するのは画風と人物同一性であり、コマ割り・表情・ポーズ・会話展開ではない。全ページを「同じ導入顔→説明→四つのポイント→ここが大事」にしない。毎回同じ驚き顔・指さし・納得の笑顔を使い回さない。
- 生成後は実画像の縮小一覧と通読で反復を検査する。初期2〜3ページでも比較し、単調化した設定を残り全部へ展開しない。VISUAL GATEがFAILまたは未確認なら完成扱いにしない。実画像を見ていない評価を補わない。
- 4コマや比較などの意図した反復は対象と効果を記録して許可する。同じコマ数だけで不合格にせず、差分の数を稼ぐために読み順・人物・空間の連続性を壊さない。

## 作業場所・制作・引き渡し

- ここは `New-MangaProject.ps1` で作成された作品プロジェクト。作業フォルダがこの作品のルートであることを `project.json` とともに確認し、ここで漫画を制作する。配布元の制作キットへ戻って描いたり、さらに新規プロジェクトを作り直したりしない。キット内での例外制作を示すファイルは不要。雛形原本として読んでいる段階では、配布元の `AGENTS.md` に従って個別プロジェクトを作る。
- 漫画はまずPNGプレビューを提示し、修正があれば反映・再提示して、ユーザーに修正がないことを確認する。PSD作成の指示がない場合はいったん作らず、作るか聞いて回答を待つ。既にPSD作成の指示がある場合は再確認せず、PNGの修正確認後に作成・検証・引き渡しへ進む。返答がない状態を「修正なし」や作成指示とみなさない。PSDを依頼された場合の完成条件は `docs/knowledge/psd-handoff.md`。原則、人間がCLIP STUDIO PAINTで仕上げてから外部公開する。CBZはユーザーの明示指定がある場合だけ作成する。
- 説明・ノウハウ・記入項目・引き継ぎ・レイヤー名は日本語にする。日本語として通じるカタカナ語は使用可。製品名、出典URL、パス、機械用識別子は維持する。

- 一つのプロジェクトで一つの漫画を制作する。作品設定は `docs/story/`、整理した判断・出典・進捗は `docs/` に残す。
- 再開時は `docs/PROGRESS.md` と `docs/PLAN.md` を読む。着手・判断変更・生成/検証・中断の節目に現在地と次の行動を更新する。
- 共通知識は `docs/knowledge/`。必要な観点だけ読み、相談・レビュー時は `.agents/skills/` の該当Skillを使う。重点は `config/review-profiles.json` の1～5とシーン上書きに従う。
- メインエージェントが制作方針とレビューの採否を統合する。Skillを手順として参照し、必要に応じて対象・目的・重点を渡してサブエージェントへ委任する。
- 映画的演出を動画で試すよう依頼された場合のみ `.agents/skills/manga-video-previsualization/SKILL.md` を使う。通常の漫画制作では動画生成を挟まない。動画の条件・速度・採否も作品側のdocsへ記録する。
- 漫画の脚本、字コンテ、ネーム前のセリフ・モノローグ・ナレーションを作るときは `.agents/skills/manga-script-writing/SKILL.md` を使う。`docs/knowledge/manga/10-natural-japanese-dialogue.md` の自然日本語パスを通し、人物の年齢・関係・感情に合う言葉へ直してから作画へ進む。学習漫画では教材の固定原文を自由会話と分け、固定原文を勝手に自然化しない。
- 画像生成前に `docs/production/DIALOGUE.md` へ、読者に見せるセリフ・モノローグ・ナレーション・説明枠を確定原文としてロックする。画像生成AIへ新しいセリフや説明を即興させない。画像内の文字は確定原文と照合し、誤字・脱字・言い換え・追加があれば確定しない。
- セリフとモノローグは縦書き。絵中の短い説明は横書き可。読み順と感情への効果を優先し、意図的な例外は理由を記録する。
- 日本向けのページ漫画は、ユーザーが別形式を明示しない限り **右から左、上から下** を基本の読み順とする。最初のコマは原則右上。同じ段では右のコマを先に読み、上段から下段へ進む。
- 作画・画像生成の前に、各ページのコマを「コマ1＝右上、コマ2＝左上…」のように位置と読む順で内部設計する。大ゴマや変形コマを使っても、番号なしで同じ順番をたどれる紙面にする。
- 画像生成時は毎ページ、`READ ORDER LOCK: 日本の右開き漫画。右上から開始し、同じ段は右→左、上段→下段。左→右の欧米コミック式にしない。` と同等の明示的な読み順指定を入れる。フキダシ、モノローグ、説明枠、効果音、人物の向き・視線・動線も右→左の読みを支えるように配置する。
- 左→右にしか読めないページ、同段の順が曖昧なページ、吹き出しのせいで会話順が逆転するページは確定扱いにしない。PNGプレビュー時は `.agents/skills/manga-readability-review/SKILL.md` を使い、実際に右上からコマと文字を順番にたどる。逆流や迷いがあれば、コマ配置・サイズ・フキダシ位置を修正してから完成扱いにする。
- ユーザーが白黒・モノクロ・グレースケールを明示していない限り、漫画は **フルカラー** を標準とする。画像生成時は毎ページ `FULL COLOR / フルカラー漫画ページ / モノクロ・白黒・グレースケールではない` と同等の指定を明示する。「漫画風」「商業漫画風」などの語から白黒へ自動的に寄せない。
- 白黒を使うのは、ユーザーが明示した場合、または白黒であること自体に明確な媒体・演出上の理由がある場合だけとし、理由を `docs/production/ART-DIRECTION.md` に記録する。ユーザー指定なしで生成結果が実質モノクロになった場合は仕様未達として再生成し、そのページを後続ページの画風基準に採用しない。
- 最終画像を高画質で作るときは `.agents/skills/manga-high-resolution-output/SKILL.md` と `docs/knowledge/high-resolution-output.md` を使い、`config/image-output.json` の設定を読む。学習漫画・教材漫画の最終版では、明示的なImage API設定が利用でき実行時に対応が確認できる場合、`gpt-image-2.5-sunburst` / `2400x3392` / `quality=max` / PNG を第一候補とする。高解像度設定は実出力のピクセル寸法を検証し、指定できない環境で適用済みと扱わない。
- 文字量の多い教材漫画では、高解像度化と文字の正確さを別工程で監査する。`docs/production/DIALOGUE.md` の確定原文と画像内文字を照合し、誤字・脱字・文字化け・意味変化が1つでもあればFAIL。可能なら絵を高解像度化してから正しい文字を別レイヤーまたは後工程で配置する。
- 高画質PDFは採用済みPNGをダウンサンプリング・JPEG変換・品質劣化付き再圧縮してはならない。PDF作成後はページ数・ページ順・各ページの実ピクセル寸法を確認し、可能なら元PNGと抽出画像のデコード後ピクセル一致も検証する。軽量版が必要なら高画質マスターとは別ファイルとして作る。
- `docs/knowledge/glossary.md` はレビュー時のみ使う。作品用語は `docs/story/TERMS.md` でレビューする。
- フィードバックは「残してほしい」と依頼された場合だけ `docs/feedback/` へ記録する。依頼がなければ記録するかの質問、還元候補の維持、「新規知見なし」の報告は不要。通常の進捗・制作判断・生成条件・検証記録は必要な範囲で残す。手順は `docs/knowledge/feedback-workflow.md`。
- APIキーは作品ごとの `.secrets/` またはローカル環境変数で管理し、docs・共有テンプレート・画像メタデータ・フィードバックに書かない。
- `wait_agent` 使用時は推定残り時間の2倍を範囲内の `timeout_ms` として明示し、不明なら既定時間を明示する。この記載自体はエージェント委任を指示するものではない。

- ノウハウの入口は `docs/MANGA-KNOWHOW.md`。漫画の企画・字コンテ・ネームを主軸にし、映画・ドラマや `screenwriting-skills` は必要箇所だけ参照する。映画コンテを毎回作る工程にはしない。
- PNGの確認対象・回答とPSD作成指示の有無、PSDの仕様・検証・セリフ原文・人間へ残す仕上げは `docs/production/PSD-HANDOFF.md` と `docs/production/DIALOGUE.md` に記録する。PNG確認待ち・PSD作成回答待ちは正規の待機段階とし、依頼済みのPSDは作成・検証・引き渡しまで完了扱いしない。完成の依頼にPSDの自動作成、CBZ作成や外部公開を含めない。

# 高解像度漫画画像・ロスレスPDF運用

確認日: 2026-09-17。対象: 漫画ページ、特に学習漫画・教材漫画の最終画像とPDF化。

この文書は、**公式仕様として確認できた事実**と、この制作キットで採用する**制作上の方針**を分けて記す。実行時には現在のAPI・ツールが同じ機能を提供しているか再確認し、利用できない設定を使ったと主張しない。

## 1. 公式仕様として確認できたこと

### OpenAI GPT Image 2.5

OpenAI公式モデル情報では、`gpt-image-2.5-sunburst` は画像生成・編集向けの高性能モデルとして公開され、`low` / `medium` / `high` / `xhigh` / `max` / `auto` のqualityをサポートする。

OpenAI Python SDKのOpenAPI由来型定義では、`gpt-image-2.5-sunburst`、`gpt-image-2.5-flare`、`gpt-image-2` などは `WIDTHxHEIGHT` の任意サイズ文字列を受け付ける。確認時の条件は次の通り。

- 幅・高さはともに16の倍数
- 縦横比は1:3〜3:1
- 最大辺は3840px以下
- 現行のピクセル数・辺長上限を満たすこと
- 2560x1440を超える解像度はexperimental扱い
- GPT Image系の既定出力形式はPNG
- `gpt-image-2.5-sunburst` / `flare` は `xhigh` / `max` qualityをサポート

本キットの教材漫画向け候補 `2400x3392` は、2400と3392がともに16の倍数、総画素数8,140,800、縦横比約1:1.413、最大辺3392pxで、確認時の上限条件内に収まる。ただし2560x1440を超える領域に該当するため、**experimentalな高解像度設定として扱う**。

### ChatGPT内蔵画像生成とAPI設定は同一ではない

OpenAI CodexのImageGen資料は、内蔵の画像生成ツールとImage API / CLI fallbackでは公開される制御項目が同一ではないと明記している。したがって、ChatGPT内蔵画像生成だけを使った場合に、API用の `model` / `quality` / 任意 `size` が実際に適用されたと断定しない。

### Real-ESRGAN

Real-ESRGAN公式リポジトリには、アニメ画像向けの `RealESRGAN_x4plus_anime_6B` が公開されている。また推論コードは `--outscale` による任意倍率の最終出力をサポートする。ただしこれは復元・超解像処理であり、元画像に存在しない文字の正しさを保証するものではない。

## 2. 本キットの最終出力方針

### 原則: 後段アップスケールよりネイティブ高解像度を優先

最終画像では、利用可能な生成環境が明示的な高解像度指定をサポートする場合、まず**最終解像度に近いサイズで直接生成**する。低解像度生成を無条件で2倍・4倍にする運用を標準にしない。

学習漫画・教材漫画の最終ページは、実行時に対応が確認できる場合、次を第一候補とする。

- model: `gpt-image-2.5-sunburst`
- size: `2400x3392`
- quality: `max`
- output format: `png`
- background: 作品仕様に従う

この値は**希望値ではなく実行後に実ピクセル寸法を確認する**。生成APIが拒否した、現在の環境にその設定がない、または品質が不安定な場合は、勝手に「2400x3392で作成済み」と扱わない。

### フォールバック

高解像度指定が失敗した場合は、縦横比を大きく崩さない範囲で、現在のAPIが受け付ける最大の検証済みサイズへ下げる。候補は `config/image-output.json` を参照する。

フォールバック時は以下を必ず残す。

1. 要求したサイズ
2. 実際に生成できたサイズ
3. 使用モデル
4. quality
5. 出力形式
6. フォールバック理由

## 3. 文字が多い教材漫画の品質ルール

高解像度化と文字の正確さは別問題として扱う。

読者に見せる文字は `docs/production/DIALOGUE.md` の確定原文を正とする。

### 最終合格条件

- 日本語・英語・数字・記号が確定原文と一致する
- 文法教材では、学習項目の例文・用語・式を勝手に言い換えない
- `will have + 過去分詞` などの構文を画像AIの見た目だけで正しいと判断しない
- 小さい文字が高解像度化で潰れていない
- 文字化け、脱字、重複、意味の変化が1つでもあればFAIL

### 推奨制作順

文字量が多いページでは、可能なら次の順を優先する。

1. 背景・人物・コマ・フキダシ等の絵を高解像度で生成
2. 確定原文を別レイヤーまたは後工程で配置
3. 文字と絵を合成
4. 最終サイズで全ページを目視監査

画像AIに文字を直接描かせる場合も、生成画像を完成原稿とみなさず、確定原文との照合を必須にする。

## 4. アップスケールを使う場合

ネイティブ高解像度生成が使えない、または既存の低解像度資産を再利用する場合だけアップスケールを検討する。

アニメ・漫画絵では `RealESRGAN_x4plus_anime_6B` を比較候補にできる。ただし次を守る。

- 文字入り完成画像にいきなり適用しない
- 可能なら**絵だけをアップスケールし、その後に文字を再配置**する
- 顔・線・手・細線・スクリーントーン・輪郭の変形を比較する
- `face_enhance` は画風を変える可能性があるため自動で有効化しない
- 元画像、ネイティブ高解像度版、アップスケール版を同じ表示倍率で比較して採否を決める

アップスケール後にピクセル数が増えただけで「情報量が増えた」「ネイティブ2K/4K」と表現しない。

## 5. PDF化は再圧縮しない

最終PDFでは、採用済みPNGを**ダウンサンプリング・JPEG変換・品質指定付き再圧縮しない**。

### 必須条件

- 元PNGの縦横ピクセル数を維持する
- JPEGへの変換禁止
- PDF作成時の自動画像縮小を無効にする
- ページサイズに合わせるために画像ピクセルそのものを縮小しない
- 可能な限りロスレス圧縮・ロスレス埋め込みを使う

### PDF検証

PDF作成後、各ページを検証する。

1. ページ数が元画像数と一致
2. ページ順が一致
3. PDFから抽出・復号したページ画像の縦横ピクセル数が元PNGと一致
4. 可能な場合は、元PNGと抽出画像を同じ色空間へ正規化して**デコード後のピクセル値が一致**するか比較
5. 一致しない場合は、PDF化による変換内容を調べ、画質劣化がないことを確認できるまで完成扱いにしない

ファイルサイズを小さくするためだけの品質低下は行わない。軽量版が必要なら、**高画質マスターとは別ファイル**として作る。

## 6. 「2K」「4K」と呼ぶときのルール

マーケティング的な呼び方ではなく、実ファイルのピクセル寸法を優先する。

- 実ピクセル寸法を必ず記録する
- 生成指示だけを根拠に「2K」「4K」と断定しない
- 2400x3392のような縦長教材ページは、その寸法をそのまま表記する
- アップスケール版は「AIアップスケール 2x」等と区別する

## 7. A/Bテスト

新しいモデル・解像度・アップスケーラーを導入するときは、20ページ等を一括処理する前に代表1ページで比較する。

比較項目:

- 顔・手・細線
- 文字の可読性と正確さ
- 背景ディテール
- キャラクター同一性
- 色のにじみ・輪郭
- 最終PDFでの見え方
- 生成時間とコスト

A/B結果が不明な場合は「高解像度だから自動的に高品質」とは判断しない。

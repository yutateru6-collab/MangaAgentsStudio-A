# 漫画の画像制作とPSD引き渡し

このSkillは漫画プロジェクト一式に同梱する。以下のパスは作業対象プロジェクトのルート基準。配布元で原本を試す場合は重点設定に `templates/manga-project/config/review-profiles.json` を指定する。

対象シーン・狙い・入力（あらすじ/字コンテ/ネーム/原稿/参照絵）を確認し、`docs/knowledge/review-workflow.md` に従って実効重点を読む。担当する主観点は `characterConsistency`。内容の判断には `docs/knowledge/ai-production.md` の該当箇所を参照する。

複数ページ・複数枚を生成する場合は、画像生成前に `manga-art-direction` の方針と `docs/production/ART-DIRECTION.md` のStyle Lockを確認する。Style Lockが未作成なら、先に時代設定・ジャンル・読者層・白黒/カラー・線・人物造形・トーン/彩色・背景密度・光と影・デフォルメ度を決める。ページごとの内容は変えてよいが、作品全体のStyle Profileをページごとに勝手に変更しない。キャラクター参照と画風参照は分け、前者は顔・髪・体格・衣装などの同一性、後者は線・色・トーン・質感・背景密度などの一貫性に使う。

## 画像生成前の必須入力

漫画ページを生成する前に、最低限次を確認する。

- `docs/story/TEXT-STORYBOARD.md` にページごとのコマ順がある
- `docs/production/ART-DIRECTION.md` にStyle Lockがある
- `docs/production/DIALOGUE.md` に読者へ見せる文字の確定原文がある
- キャラクター参照または固定特徴がある

セリフ・モノローグ・ナレーション・説明枠がまだ未確定の場合は、先に `manga-script-writing` を使って自然日本語パスを通し、`DIALOGUE.md` をロックする。ラフな構図だけを試す明示依頼を除き、画像生成時になって初めて本文を考えない。

## 日本漫画の読み順と生成前ネーム

日本向けのページ漫画を生成する場合、ユーザーが左開き・Webtoon・海外コミック等を明示しない限り、読み順は **右から左、上から下** とする。最初のコマは原則として右上。同じ段に複数コマがある場合は右のコマを先に読み、上段を読み終えてから下段へ進む。

複数コマのページを生成する前に、ページごとの **コマ番号つき内部ネーム** を必ず作る。最低限、各コマについて次を固定する。

- コマ番号
- ページ内の位置（右上 / 左上 / 右中 / 左中 / 右下 / 左下など）
- そのコマで起きる出来事
- セリフ・モノローグ・説明枠の読む順
- 次に読むコマ
- 大ゴマ・縦長コマ・変形コマを使う場合の視線の出口

例:

- コマ1（右上）: 状況提示
- コマ2（左上）: 相手の反応
- コマ3（右中）: 情報の追加
- コマ4（左中）: 感情の変化
- コマ5（右下）: 転換
- コマ6（左下）: 小さなオチまたは次ページへの引き

これは固定の6コマ形式ではなく、読む順を明示するための例である。コマ数や大きさは作品に合わせて変えてよいが、**番号を消しても同じ順番で自然に読める紙面**にする。

### READ ORDER LOCK

画像生成プロンプトには、毎ページ、次と同等の意味を明示する。

`READ ORDER LOCK: 日本の右開き漫画。1コマ目は右上。各段は右→左、上段→下段。フキダシも右上→左下。左→右の欧米コミック式レイアウトにしない。番号を表示しなくても同じ順番で読めること。`

さらに、

- 人物の視線・身体の向き・動線も次に読むコマを妨げない
- 均等グリッドでも読む順を曖昧にしない
- 大ゴマや変形コマを使っても前後関係を明確にする
- 後のセリフや結論を上・右へ置いて先読みさせない

を確認する。

**日本向け漫画ページで左から右へ読む配置のまま確定扱いにしてはならない。** 生成後は `manga-readability-review` を使って実際に右上からコマと文字を順番にたどる。読み順が逆流する、複数の入口ができる、後のフキダシを先に読んでしまう等の問題があれば、コマ配置・サイズ・フキダシ位置・人物の向きを修正して再生成する。

## フルカラーを既定値として固定する

ユーザーが白黒・モノクロ・グレースケールを明示していない場合、生成物は **フルカラー漫画ページ** とする。

画像生成プロンプトには毎ページ、次と同等の意味を明示する。

`COLOR LOCK: FULL COLOR Japanese manga page. ページ全体をフルカラーで彩色する。白黒・モノクロ・グレースケール・スクリーントーン主体の白黒漫画にしない。`

Style Lockがカラーの場合は、さらに色温度・主要パレット・肌・髪・制服・背景・光源の色を具体化する。「漫画」「商業漫画風」「少年漫画風」「少女漫画風」という語だけで白黒へ寄せない。

### カラーFAIL条件

ユーザーが白黒を指定していないのに次のいずれかなら仕様未達として再生成する。

- 全体が実質グレースケール
- 肌・髪・服・背景がほぼ無彩色で、カラー指定が視覚的に成立していない
- 1ページ目が白黒だったことを理由に2ページ目以降も白黒へ合わせている
- `ART-DIRECTION.md` がフルカラーなのに出力がモノクロ

白黒で出た1枚目をStyle Lockの新基準として採用してはならない。

## 確定セリフ以外を画像AIに書かせない

読者に見える文字は `docs/production/DIALOGUE.md` の確定原文を基準とする。

画像生成AIへ次を任せない。

- 新しいセリフ
- 新しいナレーション
- 勝手な言い換え
- 教材内容の要約
- ページ固有のキャッチコピー
- それっぽい日本語の補完

生成プロンプトでは、必要な文字がある場合は確定原文をそのまま指定する。画像AIが文字を正確に描けない環境では、絵と文字を分離して後工程で配置する方を優先する。

画像内に直接生成した文字は確定原稿ではない。PNG確認時に `DIALOGUE.md` と照合し、誤字・脱字・文字化け・意味の変化・不自然な追加が一つでもあれば修正対象とする。

## キャラクター一貫性

キャラの固定特徴、参照絵、変更したい要素、利用可能な環境を確認する。反復比較はComfyUI、局所編集は利用可能な画像編集機能を候補とし、NovelAI出力をComfyUIで絵柄へ寄せる場合は元の特徴を残す条件も記録する。指定モデル名の実在と互換性を調べ、未導入を勝手に導入済みと扱わない。seed固定だけでキャラ一貫性を保証しない。実験はdocs/experiments/TEMPLATE.mdの形式で条件・試行数・失敗・結果を残し、未生成なら未実証と明示する。認証キーの値を回答やログへ書かない。画像生成・編集時は環境にある対応Skillの必要な手順を確認し、提供されていないツール/APIをあるものとして実行しない。

画像内の日本語文字・ルビは `docs/knowledge/ruby-policy.md` と作品の読者設定に従う。自然な日本語の判断は `docs/knowledge/manga/10-natural-japanese-dialogue.md` と確定済み `DIALOGUE.md` に従う。

## PNGプレビューの必須監査

PNGを提示する前に、少なくとも次を別々に確認する。

1. **読み順**: 右上から右→左、上→下に一意に読めるか
2. **色**: 白黒指定がない限り、実際にフルカラーとして見えるか
3. **文字**: `DIALOGUE.md` の確定原文と一致するか
4. **人物**: 顔・髪・衣装・体格・小物が前ページとつながるか
5. **場面**: 字コンテの行動・感情・場所が描けているか

絵として魅力的でも、1〜3のいずれかにFAILがあれば完成扱いにしない。

結果は対象箇所、観察、読者への影響の仮説、重大度、改善案、失う効果を含める。依頼が相談なら提案と選択理由を示す。レビューでは問題なしや判断不能も正直に記録する。最終的な採否はメインエージェントが統合して `docs/reviews/` に残し、再利用できる結果のフィードバックは、ユーザーが記録を依頼した場合だけ `docs/feedback/` に残す。依頼がなければ記録するかの確認も行わない。

漫画を完成させる依頼では `docs/knowledge/manga/08-workflow-review.md` と `docs/knowledge/psd-handoff.md` を読み、まず制作素材からPNGプレビューを作成・点検して提示する。修正があれば反映・再提示し、最新のPNGについてユーザーに修正がないことを確認する。PSD作成の指示がなければ作るか聞いて回答を待ち、まだ作らない。PNGへの「修正なし」や返答なしをPSD作成指示とみなさない。既に作成指示がある場合は再確認せず、PNGの修正確認後にPSDの作成・検証・引き渡しへ進む。

絵・文字・フキダシなど実際に分けて制作できる範囲をPSD作成前から保持し、確定セリフを `docs/production/DIALOGUE.md` に残す。確認対象のPNG・版・回答とPSD作成指示の有無を `docs/production/PSD-HANDOFF.md` と進捗へ記録する。依頼されたPSDは再読込・レイヤー・確認済みPNGとの合成結果の照合・全ページの通読を行い、仕様・未確認事項・統合済みの箇所・人間に残す仕上げを記録して引き渡す。PNG確認待ち・PSD作成回答待ちは正規の待機段階とする。PNGだけ・相談・部分生成だけの依頼はその対象で完了する。

原則、人間がCLIP STUDIO PAINTで仕上げてから外部公開する。CBZはユーザーの明示指定時だけ作成する。PSDに文字層があってもCLIP STUDIO PAINTで文字が再編集できると仮定しない。実読込を確認できない場合は未確認と明記する。説明とレイヤー名は日本語にする。

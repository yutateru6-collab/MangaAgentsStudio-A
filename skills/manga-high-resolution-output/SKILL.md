# 漫画の高解像度出力とロスレスPDF

このSkillを使う前に `docs/knowledge/high-resolution-output.md` と `config/image-output.json` を読む。

目的は単にピクセル数を増やすことではなく、**最終掲載・印刷サイズで、絵・文字・色・ページ順を壊さず高精細に保つこと**である。

## 1. 最初に実行環境を確認する

画像生成前に、現在使える手段を区別する。

- ChatGPT等の内蔵画像生成
- OpenAI Image API / Responses API image generation
- ローカルまたはCLIの画像生成
- 既存画像のアップスケール

内蔵画像生成とImage APIで公開される制御項目は同一ではない。`model`、`quality`、任意の `WIDTHxHEIGHT` を実際に指定できない環境で、それらを適用済みと扱わない。

## 2. 教材漫画の最終生成デフォルト

学習漫画・教材漫画の**最終版**で、OpenAI Image API等から明示的に設定でき、実行時に対応が確認できる場合は次を第一候補にする。

- model: `gpt-image-2.5-sunburst`
- size: `2400x3392`
- quality: `max`
- output format: `png`

`2400x3392` は本キットの縦長教材漫画向け既定値。高解像度領域はexperimentalであるため、APIが受理したことと、保存された実ファイルの寸法を必ず確認する。

### HIGH RESOLUTION LOCK

最終生成プロンプトまたは実行計画には、次と同等の意味を明示する。

`HIGH RESOLUTION LOCK: 教材漫画の最終版は、利用可能な生成環境で最大限のネイティブ高解像度を優先する。Image APIで対応が確認できる場合は gpt-image-2.5-sunburst / 2400x3392 / quality=max / PNG を第一候補とする。実際の出力ピクセル寸法を検証し、指定できない設定を適用済みと扱わない。`

## 3. フォールバックを勝手に隠さない

2400x3392が利用できない場合は `config/image-output.json` の候補を使い、現在のAPIで受理される最大の検証済みサイズへ下げる。

フォールバックしたら、制作記録に次を残す。

- 要求サイズ
- 実サイズ
- 使用モデル
- quality
- 出力形式
- 理由

出力が1055x1491等であるのに「2Kで生成した」と報告してはならない。

## 4. ネイティブ高解像度を優先する

優先順位は原則次の通り。

1. ネイティブ高解像度で直接生成
2. 高解像度編集・局所修正
3. 既存低解像度画像のアップスケール

既存画像しかない場合や、ネイティブ高解像度が使えない場合に限り、アップスケールを比較候補にする。

## 5. 文字の多い教材漫画は別工程で監査する

高解像度でも文字は間違う可能性がある。読者に見せる文字は `docs/production/DIALOGUE.md` の確定原文を正とする。

### TEXT ACCURACY LOCK

文字量の多い学習漫画では、次を必須とする。

- 日本語・英語・数字・記号を確定原文と照合する
- 文法式、例文、用語を画像AIに勝手に書き換えさせない
- 誤字・脱字・文字化け・重複・意味変化が1つでもあればFAIL
- 可能なら絵と文字を分け、絵を高解像度化した後に正しい文字を後置きする
- 文字を直接生成した場合も、確定原文との一致を確認するまで完成扱いにしない

特に英語教材では、英文の文法的正確さと画像内の綴りを別々に確認する。

## 6. アップスケールを使う場合

アニメ・漫画絵では `RealESRGAN_x4plus_anime_6B` を比較候補にできる。

ただし、

- 文字入り完成ページをそのままAI超解像するのを既定にしない
- 可能なら絵だけをアップスケールし、文字を後から再配置する
- 顔・手・輪郭・細線・トーン・文字の変形を比較する
- `face_enhance` を自動で有効にしない
- アップスケール後を「ネイティブ2K/4K」と呼ばない

を守る。

20ページ等の一括処理前に代表1ページでA/B比較し、採用方式を決める。

## 7. PNGを最終マスターにする

最終マスター画像は原則PNGとする。

- JPEGへ変換しない
- SNS軽量版が必要でもマスターPNGを上書きしない
- ページごとの実ピクセル寸法を記録する
- 複数ページでは全ページのサイズ・向き・色を揃える

## 8. PDFは再圧縮禁止

高画質マスターPDFを作るときは、採用済みPNGをダウンサンプリング・JPEG変換・品質劣化付き再圧縮しない。

### LOSSLESS PDF LOCK

`LOSSLESS PDF LOCK: 採用済みPNGの縦横ピクセル数を維持し、JPEG変換・ダウンサンプリング・品質劣化付き再圧縮を禁止する。PDF作成後にページ順、実ピクセル寸法、可能ならデコード後ピクセル一致を検証する。軽量版が必要なら高画質マスターとは別ファイルで作る。`

### PDF完成条件

- 元画像数とPDFページ数が一致
- ページ順が一致
- 元PNGとPDF内ページ画像の実ピクセル寸法が一致
- 可能なら抽出・復号後のピクセル値を比較し一致を確認
- 不一致の理由が確認できないPDFは完成扱いにしない

## 9. PNGプレビュー時の追加監査

既存の読み順・色・文字・人物・場面の監査に加え、次を確認する。

1. **実ピクセル寸法**: 指定と一致しているか
2. **細線**: 髪・輪郭・目・衣装の線が破綻していないか
3. **小さい文字**: 最終サイズで読めるか
4. **拡大由来の偽ディテール**: 不自然な線や文字が追加されていないか
5. **ページ間統一**: 一部だけ低解像度になっていないか

## 10. 最終報告

ユーザーへ高画質版を渡すときは、必要に応じて次を簡潔に報告する。

- ページ数
- 実解像度
- ネイティブ生成かアップスケールか
- PNG / PDFの形式
- PDFで再圧縮していないこと
- 実施した検証

設定値ではなく、**実際に作られたファイルを根拠に報告する**。
